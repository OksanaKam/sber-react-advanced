# React PRO — финальный проект

## Запуск и сравнение сборок

Команды из `final/`, Node.js `^20.19.0 || >=22.12.0` (`.nvmrc`: 22):

```bash
nvm use
HUSKY=0 npm ci
npm start             # Webpack, localhost:8080
npm run dev:vite       # Vite + SWC, localhost:5173
npm run build         # Webpack → dist/
npm run build:vite    # TypeScript + Vite → dist-vite/
npm run preview:vite # Просмотр production-сборки Vite
npm run build:compare # Повторить замеры
```

В `.env`: `API_URL=https://api.v2.react-learning.ru`. Обе сборки передают
в клиент только публичный API_URL, а не весь набор переменных окружения.
Vite использует корневой `index.html`, Webpack — `public/index.html`.
Оба содержат root и modal-root. SWC трансформирует React/TypeScript в dev
и production; production-бандл собирает Rollup через Vite.
SVG-компоненты импортируются с `?react`; SVG-картинки остаются URL.
CSS-модули и общий PostCSS-конфиг работают в обеих сборках.

### Результаты замеров

Node 22.23.3, macOS arm64. Медиана трёх последовательных запусков каждой
команды, с чередованием Webpack/Vite. Измерено полное время команды,
включая проверку типов: ts-loader у Webpack, tsc у Vite.
Минификация включена, sourcemaps выключены. Кэш зависимостей не очищался.
1 КиБ = 1024 байта.

| Сборка | Время, с | Все файлы, КиБ | JS, КиБ | CSS, КиБ | JS gzip, КиБ |
|---|---:|---:|---:|---:|---:|
| Webpack | 9,605 | 777,61 | 724,08 | 50,41 | 237,53 |
| Vite + SWC | 4,995 | 746,87 | 695,30 | 38,20 | 228,92 |

Точные данные: [build-comparison.json](build-comparison.json).
Скрипт: [scripts/compare-builds.cjs](scripts/compare-builds.cjs).
Общий размер включает все созданные файлы; gzip рассчитан для JS отдельно
и не означает, что сервер автоматически включает сжатие.

В этом замере альтернативная команда завершилась примерно в 1,92 раза быстрее.
Это сравнение конфигураций проекта: Webpack сохраняет TS target ES5,
Vite использует современный browser target; обработка ресурсов и CSS отличается.
Оба сборщика предупреждают о крупном JS-бандле.

Проверены обе production-сборки, TypeScript, ESLint, запуск Vite, отдача HTML
по / и /cart, трансформация SVG-модуля. Работа приложения через Vite
также проверена в браузере.

## Что доработано

Основа — [REACT_PRO_final_project_base](https://github.com/NelliEfr/REACT_PRO_final_project_base).
Каталог, корзина, авторизация, поиск и RTK Query уже были в исходнике.
Наши изменения:

- Бизнес-компоненты перенесены в features, конфигурация приложения — в app.
  Общие Button/Input/Modal получают данные и обработчики через props.
- Оптимизированы обновления корзины: memo для CartItem, сохранение ссылок на
  неизменённые товары в reducer и подписка счётчика на свой товар.
- Фильтрация избранного мемоизирована через useMemo. Зависимости — массив
  товаров, режим страницы и id пользователя: изменение лайков пересчитывает список.
- Сохранён полезный useCallback в useLoadMore: стабильный callback предотвращает
  пересоздание IntersectionObserver при рендерах с прежними зависимостями.
  Этот хук уже был в исходнике, мы не считаем его новой реализацией.
- Добавлено подтверждение удаления из корзины через Modal/createPortal.
- useRef применяется для DOM-фокуса и хранения таймера debounce.
- React обновлён до 19; useOptimistic меняет сердечко до ответа API и откатывает
  изменение при ошибке. Успешный ответ обновляет кэш списков и отдельного товара.
- Добавлена альтернативная сборка Vite + SWC и воспроизводимое сравнение с Webpack.

## Структура

```text
src/
├── app/       # Redux store, маршрутизация и оболочка приложения
├── features/  # auth, cart, products, favorites, search
├── pages/     # страницы, композиция фич и навигация
├── widgets/   # Header, Footer, ReviewList
└── shared/    # общие UI, хуки, утилиты, типы, ресурсы и baseQuery
```

Общая кнопка ButtonBack получает onClick со страницы; shared/ui не обращается
к Redux/API и не определяет переходы между маршрутами.

## Оптимизация и Profiler

Сценарий: три разных товара в корзине, количество первого увеличено с 1 до 2.
До изменений обновлялись все три CartItem. Reducer создавал новый объект
для каждого товара, а счётчики подписывались на весь массив корзины.
После изменений обновляется один CartItem — товар, количество которого изменилось.

На записях время commit — около 1,5 и 1,4 мс. Разница слишком мала для вывода
о значимом ускорении; ширина viewport также отличается. Подтверждённый результат —
сокращение количества обновившихся карточек с трёх до одной.
Header продолжает обновляться; отдельной оптимизации Header не выполнялось.

## Модальное окно и useRef

[Modal](src/shared/ui/Modal/Modal.tsx) рендерит нативный dialog в #modal-root.
Закрытие: крестик, Escape, фон и «Отмена». Фокус устанавливается на крестик,
при закрытии возвращается на кнопку открытия, если она осталась в DOM.
После удаления товара его кнопка исчезает. Прокрутка фона блокируется на время окна.
Компонент не знает о корзине; удаление выполняет CartItem после подтверждения.

В формах входа/регистрации ref фокусирует email. В useDebounce ref хранит
идентификатор таймера; cleanup очищает таймер, не вызывая дополнительных рендеров.

## React 19: избранное

[LikeButton](src/features/favorites/LikeButton/ui/LikeButton.tsx) использует
useOptimistic внутри transition. Пока запрос выполняется, повторный клик
заблокирован. При ошибке исходный цвет восстанавливается и показывается toast.
После успеха подтверждённый лайк сохраняется в кэше RTK Query.

Проверено: мгновенная смена цвета, блокировка повторного клика,
откат при Offline. Также подтверждена работа приложения через Vite.
Для демонстрации задержки можно включить throttling в Network; для отката — Offline.
